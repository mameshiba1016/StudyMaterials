# 参照

参照は既存オブジェクトの別名です。独立した二つ目の値ではなく、参照を通じた操作は参照先へ作用します。

## 左辺値参照

```cpp
int hp{100};
int& hpReference{hp}; // &が宣言子に現れ、intへの左辺値参照を宣言する。

hpReference -= 30;    // 参照先であるhpを変更する。
std::cout << hp;      // 70。
```

参照は宣言時に有効な対象で初期化する必要があり、後から別オブジェクトを参照するよう付け替えることはできません。`hpReference = otherHp;`は参照の付け替えではなく、`otherHp`の値を現在の参照先へ代入します。

## `const`参照

```cpp
void PrintName(const std::string& name)
{
    // name.clear(); // const参照を通じた変更はコンパイルエラー。
    std::cout << name << '\n';
}
```

大きなオブジェクトのコピーを避けながら、関数内で変更しない意図を表します。`const`は「世界のどこからも絶対に変化しない」という意味ではなく、このアクセス経路から変更しないという制約です。別の非`const`参照があれば元は変化し得ます。

## 一時オブジェクトの寿命延長

```cpp
const std::string& message{std::string{"Temporary"}};
```

この直接初期化では一時`std::string`の寿命が参照の寿命まで延長されます。ただし、すべての参照経由で同じように延長されるわけではありません。関数から一時への参照を返す、メンバーへ危険な参照を保存するなどはダングリングの原因になります。

## 右辺値参照

```cpp
std::string&& temporaryName{std::string{"Agent"}};
```

`T&&`は右辺値参照で、主にムーブセマンティクスと完全転送に使われます。「一時値なら必ず自動で高速化される」という機能ではありません。名前を持った右辺値参照変数の式は、それ自体は左辺値として扱われるため、再びムーブしたい場合は`std::move`などが必要です。

## 戻り値で参照を返す場合

参照先が呼び出し後も確実に生存し、APIの意味として共有アクセスが必要な場合だけ返します。

```cpp
class Player
{
public:
    const std::string& GetName() const
    {
        return name_; // Playerが生存し、name_が置換・破棄されない間だけ有効。
    }

private:
    std::string name_{"Player"};
};
```

呼び出し側が返された参照を長期保存すると、所有者`Player`の破棄後にダングリングします。小さな値や所有権を渡したい値は、値で返す方が安全です。コンパイラのコピー省略やムーブにより、値返しは多くの場合効率的です。

## ゲーム開発での判断

- 必須の非所有対象：`T&`または`const T&`。
- 任意の非所有対象：ポインタ、ハンドル、`optional<reference_wrapper<T>>`など設計に合う表現。
- 所有権の移動：値、`unique_ptr`など。
- 長期保持：対象の寿命を保証できる仕組みが必要。

参照はnullでない前提を表せますが、壊れた参照を作れないという保証ではありません。参照先の寿命終了後はダングリングします。
