# 列挙型（enum）

列挙型は、取り得る名前付きの選択肢を一つの型として表します。整数だけで状態を扱うより、許される値と意味がコードへ現れます。

## `enum class`

```cpp
enum class PlayerState
{
    Idle,   // 待機。
    Move,   // 移動。
    Attack, // 攻撃。
    Dodge,  // 回避。
    Dead    // 死亡。
};

PlayerState state{PlayerState::Idle};

if (state == PlayerState::Attack)
{
    // 攻撃状態の処理。
}
```

`enum class`は列挙子を列挙型のスコープ内へ置き、整数への暗黙変換を行わないため、古い非スコープ列挙`enum`より型安全です。

## 基礎型の指定

```cpp
#include <cstdint>

enum class Team : std::uint8_t
{
    Player,
    Enemy,
    Neutral
};
```

保存形式や通信形式でサイズが要件になる場合、基礎型を明示できます。ただし、列挙子を追加した際に範囲を超えないこと、外部形式の互換性を維持することが必要です。メモリ削減目的だけで乱用せず、構造体のパディングも含めて計測します。

## 明示的な値

```cpp
enum class InputAction
{
    None   = 0,
    Jump   = 1,
    Attack = 2,
    Dodge  = 3
};
```

セーブや通信へ整数値を保存すると、並べ替えや挿入で意味が変わる危険があります。外部へ永続化する値は明示し、削除した番号を安易に再利用せず、バージョニングを設計します。

## ビットフラグとの違い

通常の列挙値は「IdleまたはAttack」のように一つを選ぶ用途です。「地上にいる・無敵・入力禁止」のように複数を同時保持する場合は、型安全なフラグ型、ビットマスク、または複数の意味あるデータへ分けます。列挙値をそのまま`|`で結合できるようにするには演算子定義と不変条件が必要です。

## 状態機械との関係

列挙型だけでは状態機械は完成しません。状態ごとの更新、遷移条件、開始・終了処理、不正遷移、遷移優先度を設計する必要があります。状態が巨大化したら、状態パターン、データ駆動設計、階層型状態機械などを検討します。
