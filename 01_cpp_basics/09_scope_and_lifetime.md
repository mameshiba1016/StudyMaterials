# スコープ・記憶域期間・寿命

似ていますが別の概念です。

- **スコープ**：ソースコード上で名前を参照できる範囲。
- **記憶域期間**：オブジェクトの保存領域が存続する期間の分類。
- **寿命**：その領域に特定の型のオブジェクトが存在して使用可能な期間。
- **リンケージ**：異なる翻訳単位の宣言が同じ実体を指せるかという性質。

## ブロックスコープ

```cpp
int main()
{
    int outer{10};

    {
        int inner{20};
        std::cout << outer << inner; // 両方見えます。
    } // innerの寿命は通常ここで終わり、デストラクタが必要なら呼ばれます。

    // std::cout << inner; // 名前innerはスコープ外なのでコンパイルエラー。
    return 0;
}
```

## シャドーイング

内側で外側と同名の変数を宣言すると、外側の名前が隠れます。

```cpp
int score{100};
{
    int score{0}; // 外側のscoreを隠す。別のオブジェクトです。
}
```

合法でも読み違いを生むため、警告を有効にして避けるのが基本です。

## 自動記憶域期間

通常のローカル変数は、宣言位置へ処理が到達すると生成され、ブロックを抜けると破棄されます。実装上スタックを利用することが多いですが、C++規格の概念と物理的な配置を同一視してはいけません。最適化によってレジスタだけに存在したり、完全に除去されたりします。

## 静的記憶域期間

名前空間スコープの変数や`static`ローカル変数などは、プログラム全体に近い期間だけ保存領域が存続します。

```cpp
int GenerateId()
{
    // 初回実行時に初期化され、その後の呼び出しでも同じオブジェクトを使います。
    static int nextId{0};
    return nextId++;
}
```

関数ローカル`static`の初期化はC++11以降、複数スレッドが同時に初回到達しても一度だけ行われるよう保証されます。ただし、その後の`nextId++`自体は同期されないためデータ競合になり得ます。

## 一時オブジェクト

式の評価中に名前のない一時オブジェクトが作られることがあります。多くは完全式の末尾で破棄されますが、参照による寿命延長などの規則があります。一時オブジェクトやローカル変数への参照・ポインタを、寿命終了後まで保持するとダングリングになります。

```cpp
const std::string& MakeInvalidReference()
{
    std::string local{"temporary"};
    return local; // 関数終了時にlocalが破棄されるため、無効な参照を返します。
}
```

このような参照を使用すると未定義動作です。クラッシュする保証はなく、たまたま文字が見える場合こそ危険です。

## RAIIへの接続

オブジェクトの寿命にリソースの取得・解放を結び付ける設計をRAIIと呼びます。ブロックを抜けるあらゆる経路でデストラクタが呼ばれる仕組みを利用し、メモリ、ファイル、ロックなどを安全に解放します。後の専用ノートで詳しく扱います。
