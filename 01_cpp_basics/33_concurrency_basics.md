# 並行処理・スレッド・同期

並行処理は複数の仕事を時間的に重ね、マルチコアを利用します。正しさ、寿命、同期、粒度を設計しなければ、データ競合、デッドロック、再現困難なバグを生みます。

## `std::thread`

```cpp
#include <thread>

void Worker()
{
    // バックグラウンド処理。
}

int main()
{
    std::thread worker{Worker};
    worker.join(); // 完了を待ち、スレッド資源を回収。
}
```

join可能な`std::thread`を破棄すると`std::terminate`が呼ばれます。すべての制御経路で`join`または`detach`が必要です。C++20の`std::jthread`は破棄時joinと停止要求を扱いやすくします。

`detach`したスレッドは所有者から独立し、参照しているローカルやシステムが先に終了する危険があります。安易に使いません。

## データ競合

複数スレッドが同じメモリ位置へ同期なしにアクセスし、少なくとも一方が書き込むとデータ競合になり、未定義動作です。

```cpp
int counter{0};

// 複数スレッドから同時に実行するとcounter++は安全ではない。
++counter;
```

`counter++`は概念的に読み取り、加算、書き戻しからなり、原子的とは限りません。

## mutex

```cpp
#include <mutex>

std::mutex scoreMutex{};
int score{0};

void AddScore(int amount)
{
    std::scoped_lock lock{scoreMutex};
    score += amount;
} // RAIIでunlock。
```

保護対象とmutexの関係を明確にし、すべてのアクセスが同じ規則へ従う必要があります。ロック中に長いI/O、外部コールバック、別システム呼び出しを行うと停滞やデッドロックを招きます。

## デッドロック

複数スレッドが互いのロック解放を待ち、永久に進めない状態です。複数mutexを同時取得する場合、`std::scoped_lock lock{mutexA, mutexB};`などデッドロックを避ける仕組みと一貫したロック順を使います。

ロック順だけでなく、コールバック先で再びロックする、メインスレッドがジョブ完了待ち中にジョブがメインスレッド処理待ちになる、といった高水準の待ち循環もあります。

## `std::atomic`

```cpp
#include <atomic>

std::atomic<bool> stopRequested{false};
stopRequested.store(true);

if (stopRequested.load())
{
    // 停止処理。
}
```

特定の値への原子的操作を提供しますが、複数変数にまたがる不変条件まで自動保護しません。メモリオーダーは高度な領域で、まず既定の逐次一貫性を使い、緩和順序は証明と計測がある場合に限定します。

## condition variable

条件が成立するまでスレッドを効率的に待機させます。通知がなくても復帰するspurious wakeupがあるため、述語付きwaitまたはループで条件を再確認します。

## タスク・ジョブシステム

ゲームでは処理ごとにOSスレッドを作るより、固定ワーカースレッドへ小さな仕事を投入するジョブシステムが一般的です。依存関係、優先度、ワークスティーリング、フレーム境界、キャンセルを管理します。

## ゲーム固有の制約

- 多くの描画APIやエンジンオブジェクトは特定スレッドからのみ操作可能。
- バックグラウンドで読み込んでも、GPUアップロードやオブジェクト生成は指定スレッドへ戻す必要がある。
- ワーカーへ渡したポインタの対象がジョブ完了まで生存する保証が必要。
- フレームをまたぐ結果は世代・キャンセル・シーン遷移を扱う。
- 並列化のオーバーヘッドが処理本体より大きい小粒度タスクもある。

## 決定性

並行実行順は毎回同じとは限りません。浮動小数点加算順、イベント順、乱数消費順が変わるとシミュレーション結果が変化します。リプレイ、ロックステップ通信、テストでは決定的なマージ順と乱数ストリームを設計します。

## 調査ツール

ThreadSanitizer、Visual Studio Concurrency Visualizer、プロファイラ、ロック競合計測などを使います。ログ追加でタイミングが変わりバグが消えるHeisenbugもあるため、再現データと専用ツールが重要です。
