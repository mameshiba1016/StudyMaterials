# 数値安全性・浮動小数点・オーバーフロー

ゲームは座標、時間、HP、通貨、ID、サイズを数値で扱います。型の範囲と演算規則を無視すると、ラップ、NaN、精度低下、配列境界違反へつながります。

## 固定幅整数

```cpp
#include <cstdint>

std::int32_t health{100};
std::uint64_t assetId{0};
```

`std::int32_t`は存在する実装では正確に32ビットです。ファイル・通信仕様に有用ですが、ループや自然な整数演算まで常に固定幅にする必要はありません。`sizeof(int)`は規格上固定でないことを理解します。

## `size_t`

オブジェクトサイズやコンテナ要素数を表せる符号なし型です。

```cpp
for (std::size_t index{0}; index < values.size(); ++index)
{
}
```

逆順ループで`index >= 0`とすると、符号なしは0より小さくならずアンダーフローします。逆イテレータ、`std::ssize`と符号付き型、適切なループ構造を使います。

## 符号付きオーバーフロー

```cpp
int value{std::numeric_limits<int>::max()};
// ++value; // 符号付き範囲を超え、未定義動作。
```

演算後に範囲検査しても遅いため、演算前に条件を確認する、より広い型で安全に計算する、チェック付き演算APIを使うなどが必要です。最適化コンパイラは「未定義動作は起きない」と仮定します。

## 符号なしラップ

符号なし整数は最大値を越えると法演算でラップします。ハッシュや意図的なビット演算には利用できますが、所持金0から1を引いて巨大値になるのは通常バグです。

## 浮動小数点

IEEE 754準拠の一般的環境では、符号、指数、仮数で広い範囲を近似表現します。

- 多くの十進小数を正確に表せない。
- 値が大きいほど隣接表現間隔も大きくなる。
- `+0`と`-0`がある。
- 無限大とNaNがある。
- 演算順で丸め結果が変わる。

```cpp
float value{0.1F + 0.2F};
bool exact{value == 0.3F}; // 真とは限らない。
```

## NaN

NaNは通常、自分自身とも等しくありません。

```cpp
if (std::isnan(value))
{
    // 不正計算の発生源を追跡する。
}
```

比較がすべてfalseになり、ソート比較の契約を壊す可能性があります。0ベクトルの正規化、負値の平方根、無効な物理計算を入口で防ぎます。

## Nearly Equal

```cpp
bool NearlyEqual(float a, float b, float absoluteEpsilon, float relativeEpsilon)
{
    const float difference{std::abs(a - b)};
    const float scale{std::max(std::abs(a), std::abs(b))};
    return difference <= std::max(absoluteEpsilon, relativeEpsilon * scale);
}
```

万能epsilonはありません。座標、角度、速度、単体テストで許容誤差が違います。0付近には絶対誤差、大きな値には相対誤差が役立ちます。

## 座標原点からの距離

巨大なワールド座標を`float`で持つと細部精度が失われ、カメラ揺れや物理不安定が起きます。原点再配置、階層座標、カメラ相対レンダリング、倍精度などをエンジン規模に応じて使います。

## 金額と固定小数点

現実通貨や厳密なゲーム内経済を二進浮動小数点で扱うと端数問題が起きます。最小単位の整数、十進型、固定小数点を検討し、乗除時の丸め規則とオーバーフローを仕様化します。

## 変換前の検査

ファイルの64ビット長を32ビット`int`へ変換してから比較すると、すでに情報を失っています。元の広い型で範囲を検査し、その後に明示変換します。負数から符号なしへの変換も同様です。

## 決定性

コンパイラ設定、CPU命令、FMA、演算順、スレッド順で浮動結果が変わり得ます。ネットワークロックステップやリプレイでビット完全一致が必要なら、固定小数点、演算環境固定、決定的ライブラリ、状態同期などを設計します。
