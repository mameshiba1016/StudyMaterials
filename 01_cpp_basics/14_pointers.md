# ポインタ

ポインタは、オブジェクトや関数のアドレスを表す値を保持します。ポインタ自体も型と寿命を持つオブジェクトです。

## アドレス取得と間接参照

```cpp
int hp{100};
int* hpPointer{&hp}; // &hpでhpのアドレスを取得し、int*へ保存。

*hpPointer -= 20;    // *でポインタが指すintへアクセスする。hpは80になる。
```

宣言中の`*`は「intへのポインタ型」、式中の`*`は「指している対象へアクセス」という文脈の違いがあります。

## `nullptr`

```cpp
Enemy* target{nullptr};

if (target != nullptr)
{
    target->Update(); // p->memberは(*p).memberの簡潔な表記。
}
```

`nullptr`は何も指していないことを表す専用のポインタリテラルです。古い`NULL`や整数`0`よりオーバーロード解決で安全です。nullポインタを間接参照すると未定義動作です。

## `const`の位置

```cpp
const int* pointerToConst{&hp}; // 指すintをこのポインタ経由では変更できない。ポインタは変更可能。
int* const constPointer{&hp};   // ポインタ自体を付け替えられない。指すintは変更可能。
const int* const bothConst{&hp}; // 両方に制約。
```

右から読む方法が役立ちます。`int* const`は「constなポインタ」、`const int*`は「constなintへのポインタ」です。

## ポインタ演算

配列要素へのポインタは、同じ配列内と終端直後までの範囲で加減算や比較が定義されています。

```cpp
int values[3]{10, 20, 30};
int* current{values};       // 多くの式で配列名は先頭要素へのポインタへ変換。
int second{*(current + 1)}; // 20。1バイトではなくint一要素分進む。
```

配列範囲外のポインタ演算や、無関係なオブジェクト間の減算には厳しい制約があります。通常のゲームコードでは生ポインタ演算より、コンテナ、イテレータ、`std::span`を優先します。

## ダングリングポインタ

```cpp
int* invalid{nullptr};
{
    int local{42};
    invalid = &local;
} // localの寿命が終了。invalidのビット値は残っても、有効なintを指さない。

// std::cout << *invalid; // 未定義動作。
```

ポインタは対象の寿命を自動追跡しません。解放済みメモリ、破棄済みローカル、再確保前の`vector`要素などを指すポインタはダングリングになります。

## 生ポインタは所有権を表すか

現代C++では、生ポインタ`T*`は多くの場合「所有しない観測用アクセス」に使います。所有権は値、コンテナ、`std::unique_ptr`、必要な場合の`std::shared_ptr`などで表します。ただし、既存API、C API、エンジン固有規則では別の契約があるため、型だけで決めつけずドキュメントを確認します。

## ポインタの安全性

- nullかどうかだけでなく、対象がまだ生存しているかが重要。
- 初期化されていないポインタを使用しない。
- 所有者と利用者を設計上明確にする。
- ポインタを長期保存するなら、移動・削除・再確保による無効化を確認する。
- アドレスを整数へ変換して永続IDとして扱わない。
- マルチスレッドでは対象への同時アクセス規則も必要。
