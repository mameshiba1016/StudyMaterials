# 乱数・seed・決定性

ゲームではドロップ、拡散、AI選択、手続き生成に乱数を使います。C++標準乱数は「エンジン」と「分布」を分けます。

## 乱数エンジンと分布

```cpp
#include <random>

std::mt19937 engine{12345};
std::uniform_int_distribution<int> dice{1, 6};

int result{dice(engine)};
```

- `std::mt19937`：疑似乱数列を生成する状態機械。
- seed：乱数列の初期状態を決める値。
- `uniform_int_distribution`：エンジン出力を1～6の一様整数へ写す。

同じ実装・同じエンジン・同じseed・同じ呼出順なら、エンジンの生成列は再現できます。ただし標準分布の具体的な写像結果は実装間で同一とは限りません。クロスプラットフォーム完全再現が必要なら分布処理も仕様化します。

## 毎回seedしない

```cpp
// 攻撃のたびに現在時刻でseedし直す設計は、近い時刻で同じ列や偏りを作り得る。
```

エンジンを適切な寿命で保持し、必要な回数だけ分布へ渡します。グローバル一個だとシステム追加で乱数消費順が変わるため、戦闘、VFX、手続き生成など独立ストリームを検討します。

## `std::random_device`

非決定的エントロピー源を意図した型ですが、実装によって疑似乱数の場合もあり、速度や利用可能性も異なります。通常はエンジンのseed生成に限定し、毎フレーム大量に呼びません。

```cpp
std::random_device device{};
std::mt19937 engine{device()};
```

複数ワードで十分にseedしたい場合は`std::seed_seq`等を使います。

## 剰余による偏り

```cpp
int value{std::rand() % 6};
```

乱数源の範囲が6で割り切れなければ一部結果が多くなるmodulo biasがあります。`std::uniform_int_distribution`を使います。`std::rand`は品質、共有状態、再現管理の点でも現代C++ゲームの基本選択ではありません。

## 浮動小数点分布

```cpp
std::uniform_real_distribution<float> unit{0.0F, 1.0F};
float value{unit(engine)};
```

通常は半開区間の意図で利用しますが、丸めと仕様を確認します。確率30%なら分布値との比較を使えますが、境界の定義を統一します。

## 重み付き選択

敵行動を重みで選ぶ場合、負重み、全重み0、浮動誤差を処理します。`std::discrete_distribution`も候補です。単純なランダム選択だけでは、同じ攻撃の連続、長期未出現などプレイヤーに不公平と感じられる列が合法的に発生します。

## ゲーム向け制御

- shuffle bag：候補を袋へ入れ、使い切るまで重複を抑える。
- pity system：外れ回数に応じ確率や保証を調整。
- クールダウン：同じ行動の連続を禁止。
- 履歴重み：直近の選択へ低い重み。

確率表示がある場合、実装と説明を一致させ、地域の法規・プラットフォーム規約も確認します。

## テストとリプレイ

seedと乱数エンジン状態、入力列を記録すると再現しやすくなります。単体テストでは固定seedまたは偽乱数源を注入し、特定分岐を確実に通します。

## セキュリティ用途ではない

`mt19937`は予測可能な疑似乱数で、認証トークン、暗号鍵、公平性が攻撃対象になる抽選へ使えません。暗号学的安全性が必要ならOS・専門ライブラリのCSPRNGを使用します。
